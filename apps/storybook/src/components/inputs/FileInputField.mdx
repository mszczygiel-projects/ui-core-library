# FileInputField

<ComponentOverview name="FileInputField" />

## Usage

Use FileInputField when a form takes one file or several from the user's device: a photo, a document, a set of attachments. It chooses files and submits them with the form; it does not upload them, show progress or preview anything but images. Keep a visible label, and say in `hint` which types and sizes the field takes, since a rejected file leaves no message of its own.

## Anatomy

The **base** holds the **label** (with **label-text**), the **dropzone** and the **hint** (with **hint-text**). The zone shows the decorative **icon** and the **prompt**. A previewed image replaces them with the **preview** around the **preview-image** and the **actions**: **replace**, a Button, and **remove**, an IconButton. Several files, or one file that is not an image, are a **list** below the zone: each **item** holds the **thumb** with the **item-icon**, the **info** with the **name** and the **meta** (extension and size), and a **remove** button. A visually hidden native file input sits before the zone. The web component exposes the parts; React uses `.ui-file-input-field__<part>` classes. Figma names its layers after the same parts.

## Variants & tone

<FrameworkCanvas react={ReactStories.Variants} webComponents={WebComponentStories.Variants} />

`outline` is the default and draws a dashed border around the zone. `filled` gives the zone a filled surface with a solid border. There is no underlined variant, since an underline leaves no surface that could take a drop, and no tone prop.

## Sizes & density

`small`, `medium` (the default) and `large` set the minimum height, the padding, the gap, the icon and the type size of the zone. Each follows the surrounding density. The rows of the list keep one size.

## States

`state` is `default`, `error` or `success`. Error colours the border, the label, the prompt, the icon and the hint and sets `aria-invalid`; it never makes the field invalid. Hover and press on the zone use the active border of the outline variant. Keyboard focus on the input draws the focus ring around the zone. Files dragged over the zone show the dragover border, icon and a tint laid over the background. Disabled fields leave the tab order, ignore drops and submit nothing; their rows show disabled text.

## Content & labels

Supply `label` and `hint` in the language of the page, and include any required marker in the label. The prompt of the zone comes from `promptLabel`, else from `labels.fileInputField.prompt`; the Replace button from `replaceLabel`, else `labels.fileInputField.replace`; the name of each remove button from `getRemoveLabel(fileName)`, else `labels.fileInputField.remove(fileName)`, a whole phrase such as “Remove photo.png”. The size of a file follows `locale`, the configured locale and the browser language, in powers of 1000: “1.2 MB” in English, “1,2 MB” in Polish.

## Behaviour

- A press on the zone, or Enter and Space on the focused input, opens the file dialog of the system. Files dropped on the zone go the same way. A drag of anything but files is ignored.
- Without `multiple`, a new file replaces the value. With it, new files join the value in their order, and a file already chosen (the same name, size and modification time) is skipped.
- `accept` takes extensions such as `.png`, MIME types and wildcards such as `image/*`, and applies to the dialog and to drops, since the dialog can show every file. `maxSize` is in bytes. `maxFiles` limits a `multiple` field. A file that breaks a constraint never enters the value; the web component emits `ui-reject` and React calls `onReject(rejections, details)`, each rejection with its `file` and a `reason` of `type`, `size` or `count`. A rejection changes no validity.
- Each change emits one `ui-value-change` in the web component, with `detail.value`, `detail.reason` (`add`, `replace` or `remove`), `detail.files` (the files it added or removed) and `detail.originalEvent`. React calls `onValueChange(value, details)` with the same details.
- After a removal the focus moves to the remove button of the next file, else of the previous one, else to the input.
- The form receives one entry for each file under `name`. Without a name, without files, or while disabled, it receives none. `required` blocks submission until a file is chosen. A form reset restores the default files without an event.

<FileInputField label="Attachments" name="attachments" multiple maxSize={2_000_000}

## Accessibility

- **Pattern.** A native file input; no composite WAI-ARIA pattern applies. The input is the only control in the tab order. Its visible label names it, the hint describes it, and assistive technology reads the files it holds. The zone is a pointer and drop target without a role, since the input already offers what it does.
- **Keys.** Tab and Shift+Tab move between the input and the remove buttons. Enter and Space open the dialog from the input and activate a focused button.
- **Removing.** Each remove button names its file. The focus never falls back to the page after a removal.
- **Validation.** Explain an error in `hint` as well as with `state="error"`, and say there why a file was rejected. Browser validation messages come from the browser.
- **Shadow boundary.** The web component forwards `aria-label` to its input, for a field without a visible label. React passes ARIA attributes to its input and joins an external description with the hint.
- **Preferences.** Forced colours keep the border of the zone and of each row, and the focus ring and the dragover border use the system highlight. The layout uses logical properties, so the rows follow right-to-left text.

## Surfaces & themes

The zone, the label and the hint use the control family, which follows Light and Dark and the default, subtle, inverse and primary surfaces. The rows, the thumbs and the preview use the colours of file-input, aliases of the background, border and text roles. The translucent tints of a drag and of a hovered row lie over the background as an image, so the surface below shows through them.

The value is a list of `File` objects, not a string. The web component has `value` and `defaultValue` as properties only, since an attribute cannot hold files, and takes the attributes `max-size`, `max-files`, `prompt-label` and `replace-label`. It reflects only `name` and `disabled`, and exposes the custom states `disabled`, `dragover` and `invalid` (while `state` is `error`) to `:state()`. Its host is form-associated and offers `form`, `validity`, `validationMessage`, `willValidate`, `checkValidity()` and `reportValidity()`. React takes `value` with `onValueChange` for a controlled field and `defaultValue` for an uncontrolled one; its className, style and `data-*` attributes reach the root, and its ref, id, ARIA and native attributes reach the file input.

## Tokens

FileInputField reads the layout of file-input and the colours of `color/file-input/*` for the drag, the rows and the preview, and the shared `control/*` and `color/control/*` families for the zone, the label and the hint, plus the focus-ring roles.

## Implementation notes

- The web component associates its host with the outer form through ElementInternals. It gives the form one entry for each file with the name baked into the entries, so a new name submits at once, and copies validity from a detached file input with the same constraints, its files set through `DataTransfer`, with the rendered input as the anchor of the message. A reset restores the default files, the entries and the validity synchronously. The browser saves the files as form state, which `formStateRestoreCallback` restores without an event.
- React keeps the native input as the form control. After every change it writes the files of the value into `input.files` through `DataTransfer`, so the browser submits and validates what the field shows; a controlled field syncs it in an effect. The input carries `name` only while it holds files, since an empty named file input submits an empty entry. A reset the page cancels leaves the files alone.
- Both implementations take the choice of files from `shared/file-selection`: the filters, the dedupe, the layout of the value and the size format. Each creates an object URL for a previewed image and revokes it when the image leaves the value or the field leaves the page.
- Figma's `interaction` previews rest, active, focus and dragover, and `valueState` previews an empty field, the preview of one image and a list. Code derives them from the pointer, the focus, the drag and the value, and has no props for them.
