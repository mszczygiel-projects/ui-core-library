# Menu

<ComponentOverview name="Menu" />

## Usage

Use Menu for a short list of actions that a button opens beside it, such as the actions of a row, a page or a file, when showing them all as buttons would crowd the view.

Use SelectField or Listbox to choose a value that the page keeps, Popover for controls or content, and links in a navigation for places to go. A menu with one or two actions is better shown as buttons.

## Anatomy

The **base** holds the **trigger**, a button of the page, and the **menu**, which holds the **items**, each with an optional **item-icon** and its **item-label**. Grouped actions sit in a **group** each, with a **separator** between groups. The web component exposes these as parts and takes the trigger in its `trigger` slot; React takes it in the `trigger` prop and uses the matching `.ui-menu__<part>` classes. Figma names the layers the same way.

## Variants & tone

<FrameworkCanvas react={ReactStories.Placements} webComponents={WebComponentStories.Placements} />

Menu has no variants. `placement` sets the side of the trigger: `bottom`, the default, `top`, and `start` and `end`, which follow the direction of the text. `align` lines the menu up with the `start` edge of the trigger, the default, or with its `end` edge. When the window has no room on that side, the menu opens on the opposite one, and it always stays inside the window.

## Sizes & density

`size` takes `small`, `medium`, the default, or `large`, which set the padding and the text of the items; density changes them too. The menu is as wide as its longest action, and scrolls when it is taller than its maximum height.

## States

A menu is open or closed, and the trigger tells which with `aria-expanded`. One enabled action is highlighted at a time. A disabled action stays in the list, in the disabled colours, and the highlight passes over it.

## Content & labels

<FrameworkCanvas react={ReactStories.Groups} webComponents={WebComponentStories.Groups} />

`options` lists the actions, each with a `value`, a `label`, an optional `icon` and `disabled`, or groups of them that a rule separates. The trigger must act as a button: a Button, an IconButton or a native `<button>`. The menu is named by its trigger, or by `label` when the trigger shows only an icon. Menu adds no text of its own, so it has no labels in `configureUiCore`.

## Behaviour

<FrameworkCanvas react={ReactStories.Playground} webComponents={WebComponentStories.Playground} />

- A press on the trigger, or Arrow Down on it, opens the menu on the first enabled action; Arrow Up opens it on the last. The focus moves to the menu.
- Arrow Down and Arrow Up move the highlight and wrap around; Home and End go to the first and the last action; a typed letter goes to the next action that starts with it.
- Enter, Space or a press picks the highlighted action. The web component dispatches `ui-action` and React calls `onAction(value, details)`; the menu closes and the focus returns to the trigger.
- Escape closes it and returns the focus to the trigger; inside a modal, Escape closes the menu first. Tab, a press outside and the focus leaving close it without moving the focus.
- Each request carries a `reason`: `trigger`, `escape`, `outside`, `focus-out` or `action`. The web component dispatches the cancelable `ui-open-change` before it opens or closes; React reports `onOpenChange(open, details)` and follows `open` when the page controls it.

## Accessibility

- **Pattern.** The [WAI-ARIA menu button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/): the trigger carries `aria-haspopup="menu"` and `aria-expanded`, the menu has the role `menu` and its actions `menuitem`.
- **Focus.** The menu keeps the focus and names the highlighted action with `aria-activedescendant`, so that a screen reader announces it.
- **Names.** The trigger names the menu, or `label`. A disabled action carries `aria-disabled`; a rule between groups is a `separator`.
- **Contrast.** The text of an action keeps a contrast of at least 4.5 to 1 on the menu and on the highlight, in Light and Dark. In forced colours the highlight and the border stay visible.

## Surfaces & themes

The menu, its border, its shadow, the highlight and the separator follow the theme through the Components tokens of menu, which take the values of listbox by default; a theme can change them without changing lists. The menu opens in the top layer and takes the surface of the page around its trigger.

## Implementation notes

- Both render the menu in place, with the native `popover="manual"` attribute, so that it opens in the top layer; Floating UI places it and keeps it in the window.
- The web component writes `aria-expanded` and `aria-haspopup` on the element of its `trigger` slot and names the menu with `ariaLabelledByElements`, across its shadow root. It reflects only `open`. An icon is the SVG string of an icon of the icons package.
- React clones its `trigger` to add these attributes, an id, a ref, a press and its keys, and keeps the ref, `onClick` and `onKeyDown` of the page; a handler that prevents the default keeps the menu as it is. An icon is a React node. The menu renders closed on the server, and `defaultOpen` opens it after hydration.
- The Figma set has the variant property `size`, with the private components `.MenuItem` and `.MenuSeparator`; `open`, `placement`, `align`, `label` and `options` live only in code.
