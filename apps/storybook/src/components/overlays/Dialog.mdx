# Dialog

<ComponentOverview name="Dialog" />

## Usage

Use Dialog when the user must read, decide or enter something before going on: confirming a deletion, renaming a file, filling a short form. It covers the page with a backdrop, and the rest of the page waits until it closes.

Use Drawer for secondary content beside the page, such as filters or details, Notification for a message that does not stop the user, and a page of its own for a long task. Keep a dialog short: one decision, or a few fields.

## Anatomy

The **base** is the panel, a native `<dialog>`; its backdrop is `::backdrop`, which a page styles as `ui-dialog::part(base)::backdrop`. The **header** holds the **heading**, the **description** and the **close** button. The **body** holds the content and scrolls. The **footer** holds the actions. Below the breakpoint, the **grabber** shows above the header when the dialog can be dragged. The web component exposes these as parts; React uses the matching `.ui-dialog__<part>` classes, and Figma names the layers the same way.

## Variants & tone

<FrameworkCanvas react={ReactStories.Alert} webComponents={WebComponentStories.Alert} />

Dialog has no visual variants. `alert` makes it an alert dialog, which asks for an answer: a screen reader announces it as an alert, and a press on the backdrop does not close it. Give the least destructive action the focus with `data-autofocus`, and hide the close button when the answer is one of the actions.

## Sizes & density

<FrameworkCanvas react={ReactStories.Sizes} webComponents={WebComponentStories.Sizes} />

`size` sets the width: `small`, `medium`, the default, and `large` have the widths of their tokens and keep a margin from the edges of the window; `fullscreen` fills the window. The height follows the content up to the window, and the body scrolls beyond it. Density changes the padding and the gaps.

Below the breakpoint, 64rem, every size but `fullscreen` rises from the bottom of the window as a sheet: the full width, rounded at the top, with the actions stacked.

## States

A dialog is open or closed. While the body scrolls, a separator shows under the header where content runs on above, and over the footer where it runs on below. The close button and the actions have the states of IconButton and Button.

## Content & labels

Write the heading in `heading` and the supporting line in `description`; the heading names the dialog and the description describes it. Without a heading, `label` names it, and an `aria-label` of the page names it above both. The content goes into the default slot, or `children`, and the actions into the `footer` slot, or `footer`.

The close button is named by `closeLabel`, then `labels.dialog.close`, “Close” in English.

<Source language="ts" code={`configureUiCore({ labels: { dialog: { close: 'Zamknij' } } });`} />

## Behaviour

<FrameworkCanvas react={ReactStories.WithForm} webComponents={WebComponentStories.WithForm} />

- The page opens the dialog with `open`. It opens as a modal in the top layer, the rest of the page becomes inert and stops scrolling, and the width of the page stays.
- The focus moves to the element marked with `autofocus` or `data-autofocus`, else to the first focusable element of the content and the footer, else to the panel. It returns where it was when the dialog closes.
- Escape, a press on the backdrop, the close button, a form with `method="dialog"` and a drag down of the sheet ask the dialog to close, with a `reason`: `escape`, `backdrop`, `close-button`, `form` or `drag`. A form gives the `value` of its submit button as `returnValue`, a Button of the library included.
- The web component closes itself and reflects `open`, after `ui-open-change`, which the page may cancel to keep it open. React reports `onOpenChange(false, details)`: an uncontrolled dialog closes, a controlled one when its parent sets `open` to false.
- The browser may close a dialog after repeated presses of Escape, which no page can refuse; the dialog follows it and reports `escape`.
- A press that starts on the content and ends on the backdrop, such as a selection of text, does not close it. Escape in an open list of a SelectField or Combobox closes only the list.
- `dragToDismiss` lets the user drag the sheet down by its grabber or its header: past a quarter of its height, or with a flick, it closes; otherwise it returns.
- Setting `open` does not report a request. Two open dialogs share one lock of the scroll, with Drawer and across both packages.

## Accessibility

- **Pattern.** Dialog follows the [WAI-ARIA dialog (modal) pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) and, with `alert`, the [alert dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/). The native modal dialog makes the rest of the page inert, so Tab moves only through the dialog and the controls of the browser.
- **Keys.** Tab and Shift+Tab move through the dialog; Escape asks it to close.
- **Names.** The heading names the dialog and the description describes it; give `label` to a dialog without a heading. The grabber is decorative: every way to close stays for every user.
- **Contrast.** The heading, the description and the content have a contrast of at least 4.5 to 1 on the panel, in Light and Dark.
- **Preferences.** With reduced motion, the dialog opens without sliding or fading.

## Surfaces & themes

The panel, its text and the backdrop follow the theme through the Components tokens of the dialog. A dialog in the top layer still takes the surface of the element it is placed in.

## Implementation notes

- The web component renders the native dialog in an open shadow root and reflects only `open`; it writes no role or ARIA attribute on its host. `ui-open-change` bubbles, so check `event.target` when a SelectField inside the dialog sends its own.
- React renders the dialog in place, without a portal: the top layer lifts it above the page. It renders closed on the server and opens with `showModal()` after hydration. The ref is the native dialog; open and close it through `open`, never with its methods. React's `autoFocus` does not set the attribute, so mark the element with `data-autofocus`.
- The scroll lock and the drag gesture come from the shared package, so modals of both packages on one page share them.
- The icons come from the icons package, so a consumer's icon set must hold `close`.
- The Figma set has the variant property `size` and the boolean `hideCloseButton`; the design-only booleans `hasDescription` and `hasFooter` preview a dialog without them, and the sheet is a code-only layout.
