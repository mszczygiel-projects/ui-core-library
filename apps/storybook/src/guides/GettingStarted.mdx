# Getting started

UI Core Library gives a web application design tokens, icons and components. Every component exists twice, with one behaviour and one look: as a web component for any framework, or none, and as a React component.

- `@mszczygiel-projects/ui-core-foundations`: the design tokens as CSS custom properties, a Tailwind theme, text style classes and typed references, and the `ui-core-foundations` CLI.
- `@mszczygiel-projects/ui-core-icons`: one SVG string per icon, and the `ui-core-icons` CLI.
- `@mszczygiel-projects/ui-core-web-components`: the web components.
- `@mszczygiel-projects/ui-core-react`: the React components.

## Install

The packages are published to npmjs.com. Install the tokens, and the components of your framework:

```sh
# React 19
pnpm add @mszczygiel-projects/ui-core-foundations @mszczygiel-projects/ui-core-react

# any other framework, or none
pnpm add @mszczygiel-projects/ui-core-foundations @mszczygiel-projects/ui-core-web-components
```

Both component packages depend on the icons package. Add it yourself only to render icons of your own. All packages share one version: install the same version of each.

## Load the tokens

Import the tokens and the text styles once, in the stylesheet of your application:

```css
@import '@mszczygiel-projects/ui-core-foundations/tokens.css';
@import '@mszczygiel-projects/ui-core-foundations/typography.css';
```

With Tailwind 4, import `tailwind.css` after Tailwind instead of `tokens.css`. Its utilities then read the same tokens:

```css
@import 'tailwindcss';
@import '@mszczygiel-projects/ui-core-foundations/tailwind.css';
@import '@mszczygiel-projects/ui-core-foundations/typography.css';
```

The tokens live in the cascade layer `ui-core-tokens`, which comes after Tailwind's layers. Your styles outside any layer win over them wherever you import them. To override a token from a layer of your own, put that layer after `ui-core-tokens`:

```css
@layer theme, base, components, utilities, ui-core-tokens, app;
```

Style your own elements with roles, such as `var(--color-text-primary)`, and text with the classes, such as `ui-text-body`. [Foundations](?path=/docs/foundations-overview--docs) lists them.

## Render a component

### React

Import the components from the root of the package, and their styles once:

```tsx
import { useState } from 'react';
import { Button, TextField } from '@mszczygiel-projects/ui-core-react';
import '@mszczygiel-projects/ui-core-react/styles.css';

export function Profile() {
  const [name, setName] = useState('');
  return (
    <form>
      <TextField label="Name" name="name" value={name} onValueChange={setName} />
      <Button type="submit">Save</Button>
    </form>
  );
}
```

The components render on the server and hydrate, as in Next.js. A field is controlled with `value` and its `on…Change` callback, or uncontrolled with `defaultValue`, and it submits with its form like a native input.

### Web components

Import the module of each component you use. It defines the tag:

```ts
import '@mszczygiel-projects/ui-core-web-components/button';
import '@mszczygiel-projects/ui-core-web-components/text-field';
```

```html
<form>
  <ui-text-field label="Name" name="name"></ui-text-field>
  <ui-button type="submit">Save</ui-button>
</form>
```

```ts
const field = document.querySelector('ui-text-field');
field.addEventListener('ui-value-change', (event) => {
  console.log(event.detail.value);
});
```

The web components carry their own styles. A field takes part in its form like a native input: it submits, resets and validates. An event is `ui-<name>`, with its data in `detail`; React takes the same event as the callback `on<Name>`. The root of the package defines every tag at once, and `custom-elements.json` describes the API for editors and frameworks.

Each component page lists its props, events and slots under **API**, for the framework the toolbar chooses.

## Set the context

Attributes switch the tokens for an element and everything inside it:

```html
<html data-theme="dark">
  <body>
    <section data-surface="inverse" data-density="compact">…</section>
  </body>
</html>
```

The theme and the brand belong on `<html>`. Without `data-theme`, the page follows the system's light or dark preference.

## Render an icon

```ts
import { iconClose } from '@mszczygiel-projects/ui-core-icons';

element.innerHTML = `<span aria-hidden="true">${iconClose}</span>`;
```

An icon is `1em` square and painted in `currentColor`, so it follows the font size and colour of its parent. Import only the icons you render; a bundler leaves out the rest.

## Configure the components

The components render a few texts of their own, such as the name of a close button, in English. [Configuration](?path=/docs/guides-configuration--docs) translates them, sets the locale of dates and numbers and chooses the look of loaders.

## Your own brand and icons

The three tiers of [Theming & branding](?path=/docs/foundations-theming-branding--docs) change the look, from a few brand values on `:root` to a whole Figma file of your own. [Custom tokens and icons](?path=/docs/guides-custom-tokens-and-icons--docs) builds your tokens and your icon set.
